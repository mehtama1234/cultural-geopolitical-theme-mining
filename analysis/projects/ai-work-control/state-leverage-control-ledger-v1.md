# State-leverage control ledger v1

**Checked:** 2026-09-12  
**Status:** case-control ledger; no geopolitical leverage claim yet

## Purpose

Turn infrastructure into a control question. A physical asset or completed
project is not automatically public capability, sovereignty, or bargaining
power. Each case must be followed through operation, ownership, local incidence,
replaceability, and an observed external response.

## What the ledger supports

The cases demonstrate that project promise, realized milestone, ownership, and
public outcome are different records. Malaysia adds a documented control
transition from developer to a different operator/platform; Romania separates
infrastructure completion from the still-unverified application-migration
target. Neither establishes local benefit, sovereignty, or leverage.

The working mechanism remains conditional:

```text
external finance/technology
  -> domestic asset and operating capacity
  -> local skills, jobs, services, and control rights
  -> provider diversity and credible exit
  -> state bargaining power only if another actor changes behavior
```

## Required retrieval before a leverage finding

1. contracts, procurement awards, ownership, suppliers, customers, and renewal;
2. operating capacity, outages, service levels, cost, data location, and audit;
3. jobs, wages, training, local suppliers, tax, energy, water, and environmental
   incidence;
4. portability, interoperability, alternative providers, termination, and
   continuity during a dispute;
5. a dated negotiation, refusal, retaliation, regulatory action, or successful
   switch showing that external behavior changed.

Use a comparator with similar external exposure but more supplier diversity,
public control, local ownership, or a completed switch. Keep household price,
firm capability, infrastructure operation, and state leverage as separate
claims unless a shared unit and time order justify a connection.
